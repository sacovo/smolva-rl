# SmolVLA Reinforcement Learning Methods

This document provides an overview and in-depth explanation of the methods implemented in this repository based on the research papers located in `research/`. The core methods involve modifying a Vision-Language Model (VLM) backbone to use FAST tokens, employing a Flow Matching action expert, and using the RECAP Reinforcement Learning algorithm for policy conditioning.

## Overview

The repository implements a hierarchical action generation and reinforcement learning framework for robotics:

1.  **Fast Tokens (FAST)**: Continuous action chunks are mapped into discrete tokens using Discrete Cosine Transform (DCT) and Byte Pair Encoding (BPE). These tokens are appended to the VLM vocabulary, allowing the model to be trained with a standard autoregressive (AR) loss.
2.  **Flow Matching Action Expert**: The generated FAST tokens are primarily used to co-train the VLM backbone. The actual precise continuous actions are generated by an Action Expert using Flow Matching, conditioned on the hidden states of the VLM.
3.  **RECAP / Knowledge Insulation (RL)**: A reinforcement learning pipeline where a Critic learns to predict the remaining time to task completion. The policy is then conditioned using an advantage metric derived from the Critic's predictions, allowing it to differentiate between "good" and "bad" actions through prompt conditioning (`<advantage_positive>` and `<advantage_negative>`).

## 1. FAST Tokens (Discrete Action Tokens)

### Theory
To allow a standard VLM to generate actions using its autoregressive next-token prediction objective, continuous multi-dimensional action chunks must be discretized. This is achieved by transforming the chunks into the frequency domain (via DCT) to exploit temporal correlations across action frames, quantizing the coefficients, and encoding the resulting flattened sequence with BPE.

### Implementation

**Tokenizer (`src/lerobot_policy_smolvla_rl/fast_tokenizer.py`)**

The mathematical core of the tokenizer lies in applying a Type-II orthonormal DCT and a scaling factor $\gamma$ (referred to as `self.scale` in code).

```python
def encode_dct(self, actions: np.ndarray) -> np.ndarray:
    # 1. Apply Type-II orthonormal DCT along the time axis (axis=1)
    coeffs = dct(actions, type=2, norm='ortho', axis=1)
    
    # 2. Quantize: round(gamma * C)
    quantized = np.round(self.scale * coeffs).astype(np.int32)
    return quantized

def decode_dct(self, quantized: np.ndarray) -> np.ndarray:
    # Invert quantization and apply IDCT
    coeffs = quantized.astype(np.float32) / self.scale
    actions = idct(coeffs, type=2, norm='ortho', axis=1)
    return actions
```

These quantized coefficients are then flattened in a column-first manner. This interleaves the dimensions such that all low-frequency components are placed first, making it easier for the BPE tokenizer to learn frequent patterns.

**Model Integration (`src/lerobot_policy_smolvla_rl/smolvla_fast.py`)**
The `SmolVLAFast` model repurposes a set of tokens at the end of the VLM's vocabulary (e.g., indices `48000` to `48000 + num_fast_tokens`) as action tokens. The model is trained using a standard Cross-Entropy autoregressive loss.

## 2. Flow Matching Action Expert & Knowledge Insulation

### Theory
While FAST tokens allow the VLM to co-train on action data, they can lack the precision required for low-level control. Instead, a continuous Flow Matching formulation is used by a separate "Action Expert". To prevent the continuous MSE loss from destabilizing the VLM's discrete semantic representation, "Knowledge Insulation" (KI) is applied, actively blocking gradient flow from the Action Expert back to the VLM.

### Implementation

**Flow Matching (`src/lerobot_policy_smolvla_rl/smolvla_recap_bap.py`)**

In `compute_loss`, a noise variable $\omega \sim \mathcal{N}(0, I)$ is sampled, and a noised action sequence is interpolated linearly using a random timestep $\tau \sim \mathcal{U}(0, 1)$. The Action Expert predicts the vector field (flow), and is optimized using Mean Squared Error.

```python
# 1. Sample timestep tau and noise omega
tau = torch.rand((bsize, 1, 1), device=device)
omega = torch.randn_like(batch[ACTION]).to(device)

# 2. Interpolate to create noised actions
noised_actions = tau * batch[ACTION].to(device) + (1 - tau) * omega

# 3. Predict the flow via the expert
expert_input = self.action_in_proj(noised_actions.to(self.vlm_with_expert.vlm.dtype))
expert_outputs = self.vlm_with_expert.lm_expert(
    inputs_embeds=expert_input,
    encoder_hidden_states=vlm_prefix_hidden.detach(), # <-- Knowledge Insulation
    return_dict=True
)
predicted_flow = self.action_out_proj(expert_outputs.last_hidden_state)

# 4. MSE Loss against the target flow
target_flow = omega - batch[ACTION].to(device)
flow_loss = F.mse_loss(predicted_flow, target_flow)
```

**Knowledge Insulation**
Note the `.detach()` in the code above. The model mathematically severs the computational graph by patching the attention layer (`_apply_ki_patch`). The expert utilizes cross-attention against the VLM hidden states without passing gradients back, ensuring the VLM is updated *only* by the AR loss.

## 3. RECAP (Reinforcement Learning via Advantage Conditioning)

### Theory
The RECAP algorithm guides the policy to generate better actions by conditioning it on its historical performance.
1.  **Critic Training**: A value function learns to predict the remaining steps to task completion based on the current state.
2.  **Advantage Conditioning**: During policy training, the expected return $V(s)$ predicted by the critic is compared to the actual return. If the actual progress is better than expected, the policy is conditioned with `<advantage_positive>`, otherwise `<advantage_negative>`.

### Implementation

**Return Calculation (`src/lerobot_policy_smolvla_rl/ds_utils.py`)**

The progress of the episode $R$ is mathematically formulated as $-(t_{rem} / T_{max})$. This bounds the return strictly between $[-1.0, 0.0]$, where $0.0$ signifies task completion.

```python
def calculate_returns(episode_lengths, max_lengths, task_idxs, episode_idxs, frame_idxs, post_goal_buffer=0):
    T = episode_lengths[episode_idxs]
    # Remaining steps until goal
    rem_steps = torch.clamp(T - post_goal_buffer - frame_idxs - 1, min=0)
    max_lens = max_lengths[task_idxs]
    
    # Normalize values between (-1, 0)
    returns = -(rem_steps / max_lens)  
    return returns
```

**Critic Mapping (`src/lerobot_policy_smolvla_rl/train_critic.py`)**

The Critic predicts a categorical distribution (C51) over 201 bins. The continuous $[-1.0, 0.0]$ return is linearly mapped to these bins to compute Cross-Entropy targets.

```python
# Map normalized returns [-1.0, 0.0] to bin indices [0, 200]
# Formula: index = (val - vmin) / (vmax - vmin) * (num_bins - 1)
normalized_indices = ((returns - config.vmin) / (config.vmax - config.vmin)) * (config.num_bins - 1)
time_to_completion = torch.clamp(normalized_indices, 0, config.num_bins - 1).long().to(device)
```

**Policy Conditioning (`train_recap.py` & `advantage_utils.py`)**

The policy uses an N-step TD advantage following the π₀.₆ paper. The advantage of an action chunk is computed as:
$$A(s_t, a_t) = \sum_{t'=t}^{t+N-1} r_{t'} + V(s_{t+N}) - V(s_t)$$

This can be rewritten using actual (Monte Carlo) returns $R_t$:
$$A(s_t, a_t) = (R_t - V(s_t)) - (R_{t+N} - V(s_{t+N}))$$

When $t+N$ is past the episode end, the advantage degenerates to the Monte Carlo advantage $A(s_t) = R_t - V(s_t)$. The expected return $V(s)$ is computed as the expected value of the critic's predicted C51 distribution: $V(s) = \sum (p_i \cdot z_i)$, where $z_i$ is the support value of bin $i$.

```python
def compute_temporal_advantage(critic, pre_critic, batch, future_batch, support, has_future,
                               actual_returns=None, future_returns=None):
    # 1. Current V(s_t)
    critic_batch = pre_critic(batch)
    _, probs = critic(critic_batch)
    v_s = (probs * support).sum(dim=-1)

    # 2. Future V(s_{t+chunk_size})
    future_critic_batch = pre_critic(future_batch)
    _, future_probs = critic(future_critic_batch)
    v_s_future = (future_probs * support).sum(dim=-1)
    v_s_future = torch.where(has_future, v_s_future, torch.zeros_like(v_s_future))

    # N-step TD advantage: (R_t - V_t) - (R_{t+N} - V_{t+N})
    future_returns = torch.where(has_future, future_returns, torch.zeros_like(future_returns))
    mc_error_current = actual_returns - v_s
    mc_error_future = future_returns - v_s_future
    advantage = mc_error_current - mc_error_future
    return advantage, v_s, v_s_future
```

This advantage is then compared against a task-specific threshold $\epsilon_l$ (set to the 30th percentile of advantage values for task $l$) to determine if the action was "good" (`<advantage_positive>`) or "bad" (`<advantage_negative>`).

# Compare advantage against task-specific epsilon_l
advantage_bool = (advantage > batch_thresholds).tolist()
