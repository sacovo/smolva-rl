# SmolVLA Reinforcement Learning Methods

This document provides an overview and in-depth explanation of the methods implemented in this repository based on the research papers located in `research/`. The core methods involve modifying a Vision-Language Model (VLM) backbone to use FAST tokens, employing a Flow Matching action expert, and using the RECAP Reinforcement Learning algorithm for policy conditioning.

## Overview

The repository implements a hierarchical action generation and reinforcement learning framework for robotics:

1.  **Fast Tokens (FAST)**: Continuous action chunks are mapped into discrete tokens using Discrete Cosine Transform (DCT) and Byte Pair Encoding (BPE). These tokens are appended to the VLM vocabulary, allowing the model to be trained with a standard autoregressive (AR) loss.
2.  **Flow Matching Action Expert**: The generated FAST tokens are primarily used to co-train the VLM backbone. The actual precise continuous actions are generated by an Action Expert using Flow Matching, conditioned on the hidden states of the VLM.
3.  **RECAP / Knowledge Insulation (RL)**: A reinforcement learning pipeline where a Critic learns to predict the remaining time to task completion. The policy is then conditioned using an advantage metric derived from the Critic's predictions, allowing it to differentiate between "good" and "bad" actions through prompt conditioning (`<advantage_positive>` and `<advantage_negative>`).

## 1. FAST Tokens (Discrete Action Tokens)

### Theory
To allow a standard VLM to generate actions using its autoregressive next-token prediction objective, continuous multi-dimensional action chunks must be discretized. This is achieved by transforming the chunks into the frequency domain (via DCT) to exploit temporal correlations across action frames, quantizing the coefficients, and encoding the resulting flattened sequence with BPE.

### Implementation

**Tokenizer (Physical Intelligence FAST, loaded remotely)**

The project does **not** ship its own DCT/BPE implementation. Instead it uses
the official FAST tokenizer published by Physical Intelligence on the Hub. In
`SmolVLAFast.__init__` (`src/lerobot_policy_smolvla_rl/smolvla_fast.py:46-53`)
the BPE tokenizer and the `UniversalActionProcessor` are loaded via
`transformers` dynamic-module loading:

```python
bpe_tokenizer = AutoTokenizer.from_pretrained(
    "physical-intelligence/fast", trust_remote_code=True
)
processor_class = get_class_from_dynamic_module(
    "processing_action_tokenizer.UniversalActionProcessor",
    "physical-intelligence/fast",
)
self.action_processor = processor_class(bpe_tokenizer=bpe_tokenizer)
# A dummy encode fixes time_horizon and action_dim for later decoding.
self.action_processor(np.zeros((1, config.chunk_size, config.max_action_dim)))
```

Internally the `UniversalActionProcessor` applies the same Type-II orthonormal
DCT along the time axis, quantizes the coefficients, flattens them low-frequency
first, and BPE-encodes the result — exactly the transform described in the
Theory section above — but the maintained upstream implementation is the source
of truth, so we do not duplicate it here.

**Model Integration (`src/lerobot_policy_smolvla_rl/smolvla_fast.py`)**
The `SmolVLAFast` model repurposes a contiguous block of tokens in the VLM's
vocabulary — indices `48000` to `48000 + num_fast_tokens` (default 1024) — as
action tokens, re-initializing their input embeddings and LM-head rows. The
model is then trained using a standard Cross-Entropy autoregressive loss over
those repurposed token ids.

## 2. Flow Matching Action Expert & Knowledge Insulation

### Theory
While FAST tokens allow the VLM to co-train on action data, they can lack the precision required for low-level control. Instead, a continuous Flow Matching formulation is used by a separate "Action Expert". To prevent the continuous MSE loss from destabilizing the VLM's discrete semantic representation, "Knowledge Insulation" (KI) is applied, actively blocking gradient flow from the Action Expert back to the VLM.

### Implementation

**Flow Matching (`src/lerobot_policy_smolvla_rl/modeling_smolvla_recap.py`)**

In `compute_loss`, a noise variable $\omega \sim \mathcal{N}(0, I)$ is sampled, and a noised action sequence is interpolated linearly using a random timestep $\tau \sim \mathcal{U}(0, 1)$. The convention matches the base `VLAFlowMatching` used by `sample_actions()` at inference: $\tau = 0$ is the clean action and $\tau = 1$ is pure noise, with target velocity $u_\tau = \omega - a$. The Action Expert predicts the vector field (flow), and is optimized using Mean Squared Error.

```python
# 1. Sample timestep tau and noise omega
tau = torch.rand((bsize, 1), device=device, dtype=expert_dtype)
omega = torch.randn_like(actions).to(device=device, dtype=expert_dtype)

# 2. Interpolate to create noised actions (tau=0 -> clean, tau=1 -> noise)
tau_expanded = tau[:, :, None]
noised_actions = tau_expanded * omega + (1 - tau_expanded) * actions
target_flow = omega - actions

# 3. Run the unified VLM+expert forward on the prefix (detached) and the
#    noised-action suffix, then project the expert's suffix outputs to the flow
suffix_embs, suffix_pad_masks, suffix_att_masks = self.embed_suffix(
    noised_actions, tau.squeeze(1)
)
(_, suffix_out), _ = self.vlm_with_expert.forward(
    inputs_embeds=[prefix_embs.detach(), suffix_embs], ...  # <-- Knowledge Insulation
)
predicted_flow = self.action_out_proj(suffix_out[:, -self.config.chunk_size:])

# 4. MSE Loss against the target flow
flow_loss = F.mse_loss(predicted_flow, target_flow)
```

**Knowledge Insulation**
KI is enforced on both sides of the graph. The VLM prefix hidden states are detached (`prefix_embs.detach()`), and *all* VLM parameters are temporarily set to `requires_grad_(False)` for the duration of the FM forward pass (their grad states are restored immediately afterward, before the AR-loss backward). The self-attention KI patch (`_apply_ki_patch`) additionally wraps the VLM self-attention in `torch.no_grad` for efficiency. Together these ensure no Flow-Matching gradient reaches the VLM through any layer — cross-attention, residual, or MLP — so the VLM is updated *only* by the AR loss.

## 3. RECAP (Reinforcement Learning via Advantage Conditioning)

### Theory
The RECAP algorithm guides the policy to generate better actions by conditioning it on its historical performance.
1.  **Critic Training**: A value function learns to predict the remaining steps to task completion based on the current state.
2.  **Advantage Conditioning**: During policy training, the expected return $V(s)$ predicted by the critic is compared to the actual return. If the actual progress is better than expected, the policy is conditioned with `<advantage_positive>`, otherwise `<advantage_negative>`.

### Implementation

**Return Calculation (`src/lerobot_policy_smolvla_rl/ds_utils.py`)**

The progress of the episode $R$ is mathematically formulated as $-(t_{rem} / T_{max})$. This bounds the return strictly between $[-1.0, 0.0]$, where $0.0$ signifies task completion.

```python
def calculate_returns(episode_lengths, max_lengths, task_idxs, episode_idxs, frame_idxs, post_goal_buffer=0):
    T = episode_lengths[episode_idxs]
    # Remaining steps until goal
    rem_steps = torch.clamp(T - post_goal_buffer - frame_idxs - 1, min=0)
    max_lens = max_lengths[task_idxs]
    
    # Normalize values between (-1, 0)
    returns = -(rem_steps / max_lens)  
    return returns
```

**Critic Mapping (`src/lerobot_policy_smolvla_rl/train_critic.py`)**

The Critic predicts a categorical distribution (C51) over 201 bins. The continuous $[-1.0, 0.0]$ return is linearly mapped to these bins to compute Cross-Entropy targets.

```python
# Map normalized returns [-1.0, 0.0] to bin indices [0, 200]
# Formula: index = (val - vmin) / (vmax - vmin) * (num_bins - 1)
normalized_indices = ((returns - config.vmin) / (config.vmax - config.vmin)) * (config.num_bins - 1)
time_to_completion = torch.clamp(normalized_indices, 0, config.num_bins - 1).long().to(device)
```

**Policy Conditioning (`train_recap.py` & `advantage_utils.py`)**

The policy uses a Monte Carlo advantage following the pre-training and specialty training formulation of the π₀.₆ paper. The advantage is computed as:
$$A(s_t, a_t) = R_t - V(s_t)$$

where $R_t$ is the actual (Monte Carlo) return from step $t$. For failed episodes, $R_t$ contains the failure penalty ($C_{\text{fail}} = 10000$), ensuring their advantages are always extremely negative ($\approx -35.0$ to $-50.0$). For successful episodes, $R_t = -t_{\text{rem}} / T_{\text{max}}$. 

The expected return $V(s)$ is computed as the expected value of the critic's predicted C51 distribution: $V(s) = \sum (p_i \cdot z_i)$, where $z_i$ is the support value of bin $i$.

```python
# Monte Carlo advantage calculation (N=T)
advantage = actual_returns - v_s
```

This advantage is then compared against a task-specific threshold $\epsilon_l$ to determine if the action was "good" (`<advantage_positive>`) or "bad" (`<advantage_negative>`). 

To prevent the thresholds from being contaminated by failed episodes, the threshold $\epsilon_l$ is computed as the 30th percentile of advantages from **successful episodes only** (matching the paper's formulation of using successful demonstration data to select the threshold).

```python
# Compare advantage against task-specific epsilon_l
advantage_bool = (advantage > batch_thresholds).tolist()
```
